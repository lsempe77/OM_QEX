# FIELD DEFINITIONS

## Outcome Fields - EXTRACT EACH OM-IDENTIFIED OUTCOME

You MUST extract ALL outcomes listed in the OM GUIDANCE section. For each one:

- **outcome_name**: Short name (use OM's outcome_category as guidance)
- **outcome_description**: Detailed description including units, measurement method
- **effect_size**: The regression coefficient, standardized mean difference, or treatment effect
- **p_value**: Exact p-value (extract the number, e.g., 0.023, not "p < 0.05")
- **standard_error**: Standard error of the estimate (often in parentheses after coefficient)
- **confidence_interval_lower**: Lower bound of 95% CI (if reported)
- **confidence_interval_upper**: Upper bound of 95% CI (if reported)
- **literal_text**: Exact verbatim text showing this outcome's estimate
  - Example: "Project | 4,408*** (1,369)" or "Asset wealth: 0.31 (0.09), p=0.001"
- **text_position**: Location in paper
  - Example: "Table 6, Row 'Project', Column '(3) Amount savings'"

## Study Design Fields

- **evaluation_design**: Type of study
  - e.g., "Randomized Controlled Trial", "Cluster Randomised Controlled Trial", "Difference-in-Differences", "Regression Discontinuity", "Instrumental Variables".
- **evaluation_design_code**:
  - 1 = Experimental (randomised assignment, including individual and cluster RCTs)
  - 0 = Quasi-experimental (including natural experiments and all non-randomised designs)

- **evaluation_method**: Free-text description of the specific method used for identification.
  - e.g., "Cluster RCT", "Difference-in-differences with fixed effects", "sharp RDD", "two-stage least squares IV", "propensity score matching".
- **evaluation_method_code**:
  - If Experimental (randomised):
    - "1" = Randomised controlled trial (individual randomisation)
    - "2" = Cluster RCT
  - If Quasi-experiment / Natural experiment:
    - "3" = Natural experiment in which exposure to treatment is random
    - "4" = Regression Discontinuity Design (RDD)
    - "5" = Difference-in-Differences (DID) / Fixed effects estimation
    - "6" = Instrumental variable (IV) estimation
    - "7" = Endogenous treatment-effects models (including endogenous switching regression, Heckman-type models)
    - "8" = Statistical matching / weighting (e.g., propensity score matching, IPW)
    - "9" = Interrupted time series (ITS)
    - "10" = Synthetic control
  - If more than one method is used, return a semicolon-separated string (e.g., "5;8").
  - If the method is unclear or not reported, set `evaluation_method_code` to null (do NOT guess).

## Statistical Fields

- **sample_size_treatment**: Number of participants in treatment group
- **sample_size_control**: Number of participants in control group

### Intervention timing structure (for computation)

Before you fill the duration fields, extract these:

If the month is unknown, use `null` for the month and still give the year.

- **EXPOSURE / FOLLOW-UP REASONING (do this INTERNALLY before filling JSON)**:
  Before you fill in `exposure_to_intervention` and `length_of_follow_up`, think through these four steps:

  1. Identify the **approximate month and year when the intervention starts**  
     (first training, group formation, first cash or asset transfer, etc.).
  2. Identify the **approximate month and year when the intervention ends**

  3. Identify the **approximate month and year of the FINAL outcome measurement**  
     (the latest follow-up survey used for the outcomes you are extracting).
  4. Compute:
     - `exposure_to_intervention` = months between (start of intervention) and (end of intervention).
     - `length_of_follow_up` = months between (end of intervention) and (final outcome measurement).

  You MUST follow these steps internally. If needed, approximate months (e.g., early 2016 ≈ January 2016, mid-2017 ≈ June 2017).

- **exposure_to_intervention**:
  - Definition: **Total duration (in months) that participants were exposed to the intervention**, computed as in step 4 above.
  - Start: when the FIRST intervention activity that is part of the programme begins.
  - End: when the LAST intervention activity ends.

    - Weeks → months (e.g., 1 week → `"0.25"`; 6 weeks → `"1.5"`).

- **length_of_follow_up**:
  - Definition: **Number of months between the END of the intervention (same end date you used above) and the date of the FINAL outcome measurement.**
  - If multiple follow-up rounds exist, use the **latest** follow-up round.
  - Convert to **months** using the same rules.
  - Return this as a **numeric string** (e.g., `"7"`, `"12"`).
  - If you cannot determine this with reasonable confidence, use **null** (do NOT guess).

## Graduation Program Components

For EACH component, classify as `"Yes"`, `"No"`, or `"Not mentioned"`.

General rules:

- Code **"Yes"** when there is **clear evidence** that the component is part of the intervention delivered to most participants (even if it is only one of several components).
- Code **"No"** only if the paper explicitly states that such a component is **not** offered or is clearly outside the programme.
- Code **"Not mentioned"** when there is **no usable information** either way. Do NOT guess.
- A single programme can legitimately have **multiple components = "Yes"**.

Component-specific guidance:

- **consumption_support**  
  *Cash or in-kind transfers intended to stabilise consumption or food security.*
  - Examples: regular cash transfers, food rations, vouchers for basic needs, top-ups to cover essential expenditures.
  - Code **"Yes"** when transfers are described mainly as income/consumption support, safety nets, or to prevent selling assets to survive.
  - If a lump-sum is clearly framed as **capital for productive investment** (business start-up, asset purchase), treat that primarily under **assets** (see below); it can still count as consumption_support if the text also emphasises food/consumption stabilisation.

- **healthcare**  
  *Health services or financing that address basic health needs.*
  - Examples: free or subsidised clinic visits, health insurance, community health workers, vouchers for health services.
  - Health **education only** (e.g., information sessions without service access) is borderline; code **"Yes"** only if there is some concrete service, subsidy, or systematic linkage to care.

- **assets**  
  *Livestock, tools, equipment, land, or capital intended as a foundation for income generation.*
  - Examples: livestock, agricultural tools, productive equipment, starter kits, or **lump-sum grants explicitly intended as capital for productive assets or business investment**.
  - Code **"Yes"** when households receive resources that are meant to build their stock of productive assets, even if the transfer is in cash rather than in-kind.
  - Pure consumption transfers with no productive framing belong under **consumption_support**, not assets.

- **skills_training**  
  *Training that builds skills to manage assets, run businesses, or increase productivity/income.*
  - Examples: technical or vocational training, business/financial management training, farming or livestock husbandry training, life-skills training linked to livelihoods.
  - Code **"Yes"** for structured group or individual training sessions.  
    Do **not** code "Yes" for brief programme-orientation meetings or simple information about programme rules.

- **savings**  
  *Mechanisms that facilitate saving money.*
  - Examples: savings accounts, savings groups (VSLAs, ROSCAs), matched savings, compulsory savings, microfinance products explicitly framed around savings, interventions whose explicit goal is to increase savings behaviour.
  - Code **"Yes"** if the programme:
    - helps participants open or use savings accounts,
    - organises savings groups or VSLs,
    - or strongly encourages/organises regular saving as a formal component.

- **coaching**  
  *Ongoing individual or small-group support beyond one-off training.*
  - Examples: regular coaching or mentoring visits, case management, home visits, follow-up meetings where staff track progress and provide tailored advice.
  - One-off training sessions **without** ongoing follow-up are **not** coaching.

- **social_empowerment**  
  *Activities that build social capital, voice, inclusion, or linkages to institutions/markets/services.*
  - Code **"Yes"** if the programme includes any of the following (even if the words "social empowerment" are not used):
    - community-building fairs or collective events,
    - activities to build social capital or community participation,
    - formation or strengthening of groups that increase voice or agency (e.g., self-help groups, producer groups, women’s groups),
    - interinstitutional networks, alliances, or linkages with public institutions, markets, NGOs, or social services,
    - explicit empowerment activities for women, youth, or other marginalised groups (e.g., rights training, leadership, advocacy, collective action).
  - Code **"No"** only if the paper clearly indicates that the intervention is purely economic with no community/empowerment or institutional-linkage elements.

# EXTRACTION RULES

1. **Use OM Guidance**: The outcomes listed below were already identified - find them in the paper using the location hints
2. **Extract ALL OM outcomes**: Every outcome in the OM GUIDANCE section should appear in your outcomes array
3. **Extract exact values**: For effect_size and p_value, extract the numerical values exactly as reported
4. **Standard errors**: Often shown in parentheses after coefficients, e.g., "4,408 (1,369)" means effect=4408, SE=1369
5. **Significance stars**: *** usually means p<0.01, ** means p<0.05, * means p<0.10
   - If exact p-value not given but stars shown, estimate: *** → 0.01, ** → 0.05, * → 0.10
6. **Missing data**: Use null for any field that cannot be found
7. **Units matter**: Include units in outcome_description (e.g., "Malawian Kwacha", "USD", "index 0-1")
8. **Intervention timing (length_of_follow_up and exposure_to_intervention)**:
   - Follow the definitions and 4-step procedure in the *Intervention Description and Timing Fields* section.
   - Always express both fields in **months**, as **numeric strings** (e.g., `"24"`, `"7"`, `"0.25"`).
   - As a sanity check, in most evaluations:
     - `exposure_to_intervention` should reflect the full programme duration; and
     - `length_of_follow_up` should usually be **shorter than** `exposure_to_intervention` (unless follow-up occurs long after the programme ends).
   - If the paper does not provide enough information to compute a value with reasonable confidence, return **null** rather than guessing.
9. **Coded evaluation fields**:
   - Only assign evaluation_design_code and evaluation_method_code when the design/method is clearly described.
   - If uncertain, leave the code fields as null rather than guessing.
10. **Graduation components (reasoning step)**:
   - Before assigning "Yes"/"No"/"Not mentioned" for the 7 components, do this internally:
     1. Read the full intervention description and list all concrete activities (e.g., lump-sum grant, training sessions, savings groups, community fairs, alliances with institutions).
     2. For each listed activity, map it to one or more of the 7 components using the definitions above.
   - Use **"Yes"** when there is any clear evidence that a component is present, even if the exact label is not used.
   - Use **"No"** only when the paper clearly states that a component is absent or not offered.
   - Use **"Not mentioned"** when there is no usable information about that component.
11. For each component, also include a one-sentence rationale explaining which phrases in the paper you used. This rationale is for internal QA; it will NOT be used in the final dataset, but you must write it before choosing "Yes", "No", or "Not mentioned".
